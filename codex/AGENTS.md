# 共通指示

- ユーザーが別の言語を指定しない限り、日本語で回答する。
- 結論と必要な根拠を簡潔に説明する。
- ファイルや設定を変更した場合、変更内容と検証結果を報告する。
- コード実装の際には、実装根拠・理由をコメントで明示する（日本語）。コードから理解できる内容は記載しない。

# リポジトリ命名ルール

- リポジトリ名は `{{サービス名}}_{{領域}}` とする。
- 同じサービスのリポジトリでは、サービス名を統一する。
- 領域は以下を例とし、必要に応じて追加する。

| 領域 | 役割 |
| --- | --- |
| `docs` | サービス全体の仕様・設計 |
| `frontend` | 画面・フロントエンド実装 |
| `backend` | API・バックエンド実装 |
| `infrastructure` | インフラ構成・環境管理 |

# サービス全体の仕様・実装の管理

- 同じサービス名を持つリポジトリを、サービス全体を構成する関連リポジトリとして扱う。
- 作業時は、参照可能な `{{サービス名}}_docs` を仕様・設計の参照元とし、関連する領域の実装も確認する。
- 仕様・実装を変更する際は、関連リポジトリへの影響と、仕様・実装間および領域間の不整合を確認する。
- 必要な関連変更を把握し、変更内容とあわせて報告する。
