# Gitのコミット・SSHプッシュ

## 実行条件

- **コミットやプッシュは、ユーザーがその操作を明示的に指示した場合のみ実行する。** コードの修正、スキルの作成、レビュー、手順の説明、スキルの呼び出しだけを実行許可と解釈しない。
- 「コミットして」はコミットのみ、「プッシュして」は既存のコミットのプッシュのみ、「コミットしてプッシュして」は両方を実行する。
- 指示の対象となるリポジトリ・変更・送信先の範囲に限る。対象が曖昧で他の作業を含むおそれがある場合は、差分を確認してから必要な点だけ質問する。
- 明示された指示の範囲で通常の操作を進める。すでに得た許可について再確認は不要。
- amend、履歴の書き換え、force push、タグや他ブランチの送信は、通常のコミット・プッシュの指示に含めない。

## 事前確認

対象リポジトリで次のコマンドを実行し、ブランチ、変更、ステージ済み差分、リモートを確認する。

```sh
git status --short --branch
git branch --show-current
git diff
git diff --cached
git remote -v
```

プロジェクトの指示に従って必要な検証を行う。無関係な変更や認証情報をコミット対象に含めない。detached HEADの場合は、対象ブランチを確認してから進める。

## リモートとの差分確認

**コミット直前とプッシュ直前に、それぞれリモートを取得し、ローカルにないコミットがないことを確認する。** 両方を依頼された場合も、コミット前の確認だけでプッシュに進まない。

対象リモートと比較先ブランチをupstreamやユーザーの指示から特定する。以下の`{{branch}}`は実際の対象に置き換える。比較先は、コミット時は対象ブランチのリモート側、プッシュ時は実際の送信先ブランチとする。プッシュURLを使って取得し、fetch用URLと送信先が異なる場合も実際の送信先を確認する。

```sh
remote=origin
remote_branch={{branch}}
remote_url=$(git remote get-url --push "$remote")
git fetch "$remote_url" "refs/heads/$remote_branch"
git rev-list --left-right --count HEAD...FETCH_HEAD
git log --oneline HEAD..FETCH_HEAD
```

`git rev-list`の出力は「ローカルにしかないコミット数 リモートにしかないコミット数」。**右側が`0`の場合のみ、依頼されたコミットまたはプッシュに進む。** 右側が`1`以上なら、ローカルが遅れているか履歴が分岐しているため停止し、ローカルにないコミットを報告する。勝手にpull、merge、rebaseを実行しない。

fetchや比較に失敗した場合は、その結果を使って先へ進まない。upstreamが未設定でも比較先を省略せず特定する。新規ブランチで比較先が存在しない場合は、`git ls-remote --heads "$remote_url" "refs/heads/$remote_branch"`が正常終了して出力が空であることを確認し、ブランチ作成が依頼の範囲内である場合のみ進む。

## コミット

まず「リモートとの差分確認」を実行し、ローカルにないコミットがないことを確認する。

対象ファイルを個別に指定する。以下のパスとメッセージは実際の変更に置き換える。既存のステージ済み変更も含めて、コミットに入る全差分が依頼の範囲内であることを確認する。無関係なステージ済み変更がある場合、勝手に解除・取り込みをせず対象を確認する。

```sh
git add .
git add -- path/to/file1 path/to/file2 # ファイルを指定する場合
git status --short --branch
git commit -m "変更内容を表すメッセージ"
git log -1 --oneline
git status --short --branch
```

変更がなければ空コミットは作らない。フックや検証が失敗した場合は原因を確認し、`--no-verify`で回避しない。

## SSHプッシュ

送信先リモートのプッシュURLがSSH形式（`git@host:owner/repo.git`または`ssh://...`）であることを確認する。SSH接続は送信先からのfetchとプッシュに使う。SSH形式でなければ、勝手にURLを変更せず停止して報告する。

まず「リモートとの差分確認」を再実行する。fetchが成功し、ローカルにないコミットがないことを確認してから、送信対象のコミットを確認してプッシュする。以下の変数は直前の確認で使った送信先をそのまま使う。

```sh
git log --oneline FETCH_HEAD..HEAD
git rev-parse HEAD
git push "$remote_url" "HEAD:refs/heads/$remote_branch"
git ls-remote --heads "$remote_url" "refs/heads/$remote_branch"
git status --short --branch
```

新規ブランチの場合は`FETCH_HEAD`との比較を省略し、送信する履歴を確認してプッシュする。

URLを直接指定したプッシュではupstreamやリモート追跡ブランチの更新を前提にしない。プッシュの正常終了と、`git ls-remote`で取得した送信先SHAが送信したHEADのSHAと一致することを確認する。

SSH認証が失敗した場合は停止して原因を報告し、HTTPSへ切り替えない。秘密鍵の表示・新規作成・登録、SSH設定やリモート設定の変更は、別途指示がない限り行わない。未知のホスト鍵や鍵の不一致は、信頼性を確認せず承認したり検証を無効化したりしない。

プッシュが拒否された場合は原因を報告する。勝手にpull、merge、rebase、force pushを実行しない。

## 結果の報告

実行した操作、コミットSHA、SSHの送信先とブランチ、検証結果を簡潔に報告する。失敗・未実行の操作はその旨を明記する。説明だけを求められた場合はコマンドを示し、実行しない。
